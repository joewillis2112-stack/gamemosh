# A 3D game to merge with Minecraft on a phone (2026-10-06)

The user: "we should probably choose a different game mix because this mix is a 2d game and a 3d game, it doesn't make sense. Find another game that's 3d that you could get running merged with Minecraft on mobile."

Pokécraft keeps its Minecraft half: MinecraftOSS worldgen in wasm, the three.js renderer, survival, and the touch controls. Only the second game changes.

## Built here, for the browser

Both were built today for wasm and loaded in Node. No phone was used.

| | Rocket League car + ball | Super Mario 64 (Mario) |

## Round 2: full 3D games in Rust (same day)

The user: "There is a great amount of games on rust now, i guarantee at least one could get running on mobile." So I went through the 3D Rust ports in VERIFIED.md and VERIFIED_ROUND2.md, and tried them.

### Duke Nukem 3D: DukeNukemRust. **Runs in a phone browser.**

[NicholasMeacoe/DukeNukemRust](https://github.com/NicholasMeacoe/DukeNukemRust) @ b4811d6. Bevy 0.14 plus Rapier 3D, pure Rust, about 40k lines.
- **Data:** the free 1996 shareware (`DUKE3D.GRP`, 11 MB, episode 1) from archive.org `3dduke13/3dduke13.zip`.
- **Patch to build for wasm** (`mobile-proto/duke3d-wasm.patch`, 14 lines):
  - getrandom 0.2 `js` and 0.3 `wasm_js`, plus `RUSTFLAGS='--cfg getrandom_backend="wasm_js"'`.
  - uuid `js`.
  - On wasm32, `Grp::open` reads the GRP baked in with `include_bytes!` (env `DUKE_GRP`), because a browser has no filesystem.
  - Then `wasm-bindgen 0.2.114 --target web`.
- **Build:** 6.5 min. 60 MB wasm, **15.7 MB gzipped** including the 11 MB of game data. Not optimised: no wasm-opt, no strip.
- **Run (headed Chromium, swiftshader, 844×390 phone emulation):**
  - The main menu loads (`mobile-proto/duke3d-wasm-menu.png`).
  - Enter, Enter, Enter goes to episode 1, then LET'S ROCK, then **E1L1 Hollywood Holocaust**, drawn with Duke's own art, pistol and HUD (`mobile-proto/duke3d-wasm-e1l1.png`).
  - W moves the player.
- **Speed: 2.3 frames a second under swiftshader** (software rendering on the CPU). This says nothing reliable about a phone GPU, but Bevy's PBR renderer is heavy. This is the main risk.
- **Not yet:**
  - The canvas is a fixed 1280×720 and gets cropped. One line fixes it: `fit_canvas_to_parent`.
  - No touch controls.
  - Audio not checked.
  - One 404 at load (not traced).
- **Fit for a merge:**
  - The player moves with Rapier's `KinematicCharacterController`, and monsters use Rapier ray casts.
  - The Build map's sector data is an `Option<Res<SectorMap>>`, used only for water and ceilings.
  - So Duke's player, weapons and monsters can run in a world whose colliders come from Minecraft blocks.
  - MinecraftOSS worldgen is Rust too, so both can live in one Bevy app, with chunks as Bevy meshes plus Rapier colliders.
- **Faithfulness: unknown.** It's a Bevy reinterpretation, not Build's own code. The README claims all 12 weapons, all enemies and a CON VM, but I only saw E1L1 load and the player move.

### Ruled out

| Port | Why |
|---|---|
| quake-psx (Quake shareware episode, full) | The game logic (`quake-core`) depends on the PSoXide PS1 SDK (fixed-point math, the PS1's geometry chip) and nightly MIPS. Porting it to wasm means replacing that SDK. Not tried |
| Seismon (Quake, Bevy) | Mid-migration. memmap2, git dependencies. Not tried |
| skate-3-rust-engine | Needs your Skate 3 Xbox 360 ISO for the skater and animations |
| Iron Doom | SDL3 (C). Doom is 2.5D |
| IW4L (MW2), star-andreas (GTA SA), HL2-RS, ByroRedux | Need installed retail data. Desktop wgpu/Vulkan. Large |
| Legend of Legaia | Already live in a browser, but needs your PSX disc. Turn-based RPG |
| Vangers (vange-rs) | Already live in a browser with a touch stick (MOBILE_PICKS.md). Its terrain is voxels too, which is a good match, but the game is obscure |

## Not built

- **Quake** (open source; the shareware data can be shipped). It is a whole game with weapons, monsters and levels, so it could give a deeper merge (monsters at night, weapons crafted, rocket jumping off blocks). But its collision and monster AI run on BSP hull traces, which would have to be rewritten for voxels. Browser builds exist (WebQuake, QuakeJS); none were built here. Rust ports are listed in VERIFIED.md (A9–A12).

## Pick (round 1, before Duke ran)

**Rocket League car and ball in Minecraft.**
- It's the user's own gold example (RL in GTA V, MERGE_EXAMPLES.md §1). This same core, by the same project, is what that GTA port runs on.
- It needs no files from the user, it's the smallest and fastest piece, and it built first try on stable Rust.
- Physics owned by one side is the clean split the merge test asks for (Q6). The car and ball are owned by the RL core; Minecraft's world is its collision world.

Mario is the strong second choice if the user has an SM64 US ROM to load. libsm64 is the more complete character (a whole moveset, health and surfaces), and mario64-in-minecraft is a ready map of the merge.

## What a merge would mean (from the merge test)

- **Q2, the host world feeds the guest's rules:** terrain is the arena. Hills are ramps, and cliffs are walls you can drive up. Water slows the car, and ice drops its friction.
- **Q3, geometry translated:** add invisible quarter-pipes where a floor meets a wall, as the GTA port does, so wall driving works on block walls.
- **Q5, the guest's verbs on the host's actors:** bumps and demolitions on mobs; the ball knocks mobs and breaks glass and leaves; supersonic hits break blocks.
- **Q8, economies cross:** boost from Minecraft fuel (coal, blaze powder); boost pads as a craftable block; goals built from blocks.
- **Q11, a global rule:** night monsters chase the ball; a creeper blast launches it.
